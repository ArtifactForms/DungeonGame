**Working Title: Blood, Fire and Wrath**

**A small collaborative dungeon action game built with Java and MeshLibCore.**

Dungeon Game is a collaborative indie game project focused on creating a compact, playable dungeon adventure while exploring game development, engine architecture, pixel art and teamwork.

Originally started as a personal project to experiment with custom engine features, Dungeon Game is evolving into a collaborative development project with a shared goal: turning an existing technical foundation into a complete and enjoyable game.

The project combines programming, pixel art, animation and game design in a small-scale environment where ideas can be explored, skills can grow and a finished product can take shape.

## Project Goals

- **Game Development:** Building a cohesive and enjoyable gameplay experience.
- **Engine Development:** Applying and improving features of our custom Java engine, MeshLibCore.
- **Pixel Art & Animation:** Creating consistent visual assets and animations.
- **Software Architecture:** Improving code quality, maintainability and modularity.
- **Collaboration:** Practicing teamwork, communication, task planning and shared development workflows.
- **Documentation:** Keeping technical decisions, asset requirements and development processes understandable and accessible.

## Gameplay Direction

Dungeon Game aims to deliver a compact first-person dungeon action experience inspired by classic titles such as DOOM II and Heretic.

The gameplay direction includes:

- Exploring dungeon environments.
- Fighting enemies.
- Collecting items and resources.
- Discovering different areas and challenges.
- Using weapons and gameplay mechanics to progress.

The exact scope and feature set will evolve during development. Our focus is on keeping the project achievable while creating a complete and enjoyable experience.

## Engineering Challenge: From Jam Prototype to Maintainable Architecture

Dungeon Game started as a small personal game jam project, with a focus on experimenting with engine features and getting gameplay systems up and running quickly.

As the project evolves into a collaborative game, one of our main engineering challenges is to transform this initial prototype into a maintainable and extensible codebase.

This includes:

- **Refactoring:** Reviewing existing systems and improving code structure without losing working functionality.
- **Separation of Concerns:** Establishing clear responsibilities between gameplay systems, engine features, rendering, input and game logic.
- **Maintainability:** Reducing unnecessary dependencies and making systems easier to understand, test and extend.
- **Collaborative Development:** Adapting the codebase and workflows to support multiple contributors.
- **Incremental Improvement:** Improving the architecture step by step instead of attempting a complete rewrite.

We see this process as an important part of the project itself. The goal is not to build an overly complex architecture, but to create a solid foundation that supports the actual needs of the game.

**A key part of this project is learning how to evolve a working prototype into a structured, maintainable and collaborative software project.**

### MeshLibCore

Dungeon Game is built on top of [MeshLibCore](https://github.com/ArtifactForms/MeshLibCore/), a custom Java engine developed alongside the game.

The engine provides the technical foundation while the game serves as a practical environment for testing, applying and improving its features.

## Collaboration

This project brings together different interests and skills in programming, game design, pixel art and animation.

We value:

- Open communication and shared decisions.
- Clear responsibilities and manageable tasks.
- Consistent coding and asset guidelines.
- Constructive feedback and continuous learning.
- A development process that is enjoyable and sustainable.

Everyone involved contributes to shaping the game, not just implementing predefined tasks.

## Development Philosophy

1. Build a playable game rather than an endless prototype.
2. Prefer finished and polished features over many unfinished ideas.
3. Improve the engine when it directly benefits the game.
4. Keep the codebase and asset pipeline understandable.
5. Refactor incrementally and avoid unnecessary complexity.
6. Document important decisions and processes.
7. Make development enjoyable and sustainable.

New ideas are welcome, but they should support the project's goals rather than expand its scope indefinitely.
